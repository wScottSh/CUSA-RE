# Cruis'n USA (N64) reverse engineering

ROM: `ROM/Cruis'n USA.z64` (big-endian, 8 MiB, SHA-1 `54a875ee0b482036fa401a6bc2b242699f0259f7`). Never commit ROM bytes or anything derived from them (`build/` is ignored).

**Push after every commit** (`git push origin main`). Standing order from the repo owner. The repo is public on GitHub.

## Sources of truth
- `segments.toml`: the code layout. Every tool reads it through `tools/layout.py`. Change layout only here.
- `symbols.txt`: hand-written names, splat `symbol_addrs` format. Overlay symbols need `rom:0xOFFSET`, because three overlays share 0x80025C80.
- `symbols.lib.txt`: generated by `tools/libsigs.py ~/tools/n64sym/src/builtin_signatures.sig`. Don't edit it.
- `decisions.tsv`: append-only decision trail. Log with the show-me-your-work `log.sh`.

## Commands
- `python3 tools/build.py` writes `build/{boot,frontend,race}.elf`, one address space per overlay, plus seed files.
- `python3 tools/check.py [--rea]` runs static predicates. Run it after any layout or symbol change.
- `python3 tools/verify_runtime.py` boots to a race in ares `n64-run` (about 3 min) and checks each segment's text in RDRAM.
- `tools/rea VIEW COMMAND ...` runs REA on a view with its names, e.g. `tools/rea race decompile 0x80105e0c --format json`.
- `tools/rea VIEW decompile-all --output build/c/VIEW` dumps all pseudocode. Strip each file's header with `sed '1,/^\/\/ pseudocode/d'`.
- `python3 tools/segscan.py ROM STATE.bst...` lists ROM ranges found in an ares save state's RDRAM.

## Tooling locations
Node 24.22.1 `~/tools/node-v24.22.1-linux-x64`, Ghidra 12.1.4 `~/tools/ghidra_12.1.4_PUBLIC`, REA `~/repos/rea`, n64-run `~/tools/ares-n64run-build/rundir/bin/n64-run` (built from `~/repos/ares`). `ARES_PILOG=FILE` makes n64-run log every PI DMA (`L W len dram cart clock`).

## Gotchas
- REA addresses resolve only at function starts or names. Other hex is treated as a file offset and fails.
- Ghidra shows pointers sign-extended (`0xffffffff8013c960`) because of the `MIPS:BE:64:64-32addr` language.
- The MCP server (`.mcp.json`) uses `build/resident.seeds.tsv`, so overlay names only appear through `tools/rea`.
- `main` data after `text_end` begins with RSP microcode. Its `jal` targets are IMEM addresses (0x84001xxx), not CPU code.
